Executive call

Three changes, in order

The current code is coherent. Most confusion comes from names that contradict the deployed product map, not from a need to redesign the runtime.

1 / Completed

Free the Playground name

The internal apps/playground was renamed to apps/eval-harness, the Studio persistence domain was extracted, and the public host moved to apps/playground without moving project data logic with it.

2 / Completed

Nest the diagram domain

The flat packages/diagram-* folders moved under packages/diagram/*. Package boundaries and all npm identities stayed stable except the intentionally renamed shared UI package.

3 / Completed

Keep routes, move logic

TanStack adapters remain under src/routes/api. Large server implementations moved out of generic src/lib into domain folders under src/server.

Package identities

Use folders for grouping, npm names for boundaries

The nested filesystem removes repeated visual noise. Most existing npm names remain explicit; the overly narrow Studio UI name gets one intentional migration.

Implemented path Package/import name Reason
packages/diagram/core @sketchi/diagram-core Typed IR and validation remain an independent package.
packages/diagram/renderer @sketchi/diagram-renderer Deterministic scene generation remains independently testable.
packages/diagram/excalidraw @sketchi/diagram-excalidraw Sketchi scene to Excalidraw adapter.
packages/diagram/generation @sketchi/diagram-generation Provider request/response and candidate parsing.
packages/diagram/agent @sketchi/diagram-agent Canonical build runtime and artifact orchestration.
packages/diagram/scenarios @sketchi/diagram-scenarios Eval-only prompts, assertions, and scenarios.
packages/diagram/ui @sketchi/diagram-ui Rename from “studio UI”; it is shared by five surfaces.
packages/studio/projects @sketchi/studio-projects Applied in phase 2 with explicit client and server exports.

Why not @sketchi/diagram/core?

npm package names allow @scope/package, not a second package namespace. That syntax would mean a subpath export from one monolithic @sketchi/diagram package, weakening Nx package boundaries and increasing the migration risk.

Implemented boundary

The filesystem groups the domain, retains explicit npm package names, and pnpm now includes packages/*/* and tools/*. The tree is ergonomic without turning seven tested packages into one.

Combined boundary

Studio exists today, inside the Playground host

apps/playground owns public Playground, Code Mode, and artifact routes. It composes the extracted project/diagram package through a thin Cloudflare adapter while retaining the sketchi-studio Worker identity.

Completed

The public host moved without a runtime cutover

The apps/playground project preserves the Worker, Cloudflare bindings, route set, and /api/studio protocol identity. Project and Worker IDs remain separate in deployment tooling.

Extracted

The domain is portable

Studio contracts and persistence now live in packages/studio/projects. The public Playground app composes it temporarily; a future authenticated Studio project can consume the same domain when it becomes a separate deployment.

API sanity check

src/routes/api is correct

These files are TanStack Start route adapters and deliberately map to HTTP paths. Hiding them elsewhere would make the framework boundary less obvious.

Keep

Thin route modules

apps/playground/src/routes/api/v1/..., api/studio/..., api/chat.ts, and routes/mcp.ts should continue to declare public transport contracts.

Moved

Substantive server code

Large *.server.ts implementations moved from src/lib to src/server/{chat,codemode,studio,bindings}. Route paths do not change.

Review decisions

Decisions retained

The completed stack separates repository decisions from durable operational identities that still require deliberate migrations.

1

Approved app identity map

eval-harness owns internal regression work; playground owns the public anonymous product and Code Mode host; packages/studio/projects owns the existing persistence domain; keep any future authenticated Studio product as a deliberate separate deployment.

2

Approved nested diagram folders

Adopt packages/diagram/* while retaining independent npm packages. This is the smallest change matching the requested ergonomics.

3

Preserve HTTP routes

Keep /api/v1, /api/studio, /api/chat, and /mcp stable during repository work. Revisit API product naming only with a versioned contract proposal.

4

Defer durable resource renames

Do not aesthetically rename R2 buckets, Pipeline streams, or externally configured Worker endpoints in the same changes. Migrate those only when there is operational value.

Secondary findings

Cleanup completed with the move

Dependency direction

Production diagram-generation is independent of eval-focused diagram-scenarios. Shared prompt contracts live with generation, so scenarios depend on runtime code rather than the reverse.

Workspace coverage

pnpm deliberately includes apps/*, packages/*, packages/*/*, and tools/*. The generator is now both an Nx project and a lockfile-backed workspace importer.

Enforced boundaries

Nx scope and type tags plus ESLint now prevent package-to-app, normal app-to-app, runtime-to-eval/app, and persistence-to-eval/ui/app imports across source, config, and Storybook files. CI requires lint and a generated-config Wrangler dry-run for every Worker alongside the workspace build and test gates.
