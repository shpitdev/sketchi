Repository architecture review / 15 July 2026

Make the tree tell the truth.

A proposed structure for the canonical Sketchi Nx and Cloudflare repository. The plan removes the Studio/Playground naming inversion, groups diagram packages as a domain, and keeps HTTP contracts stable while implementation boundaries become easier to navigate.

Proposal only No package moves applied Public URLs preserved Prepared from main@d32b494

Executive call

Three changes, in order

The current code is coherent. Most confusion comes from names that contradict the deployed product map, not from a need to redesign the runtime.

1 / Fix first

Free the Playground name

Rename the current internal apps/playground to apps/eval-harness. Before renaming apps/studio, extract its real Studio persistence domain so the combined boundary is represented honestly.

2 / Group

Nest the diagram domain

Move flat packages/diagram-* folders under packages/diagram/*. Keep package boundaries and all npm identities except the intentionally renamed shared UI package.

3 / Organize

Keep routes, move logic

Retain TanStack adapters under src/routes/api. Move large server implementations out of generic src/lib into domain folders under src/server.

Package identities

Use folders for grouping, npm names for boundaries

The nested filesystem removes repeated visual noise. Most existing npm names remain explicit; the overly narrow Studio UI name gets one intentional migration.

Proposed path Package/import name Reason
packages/diagram/core @sketchi/diagram-core Typed IR and validation remain an independent package.
packages/diagram/renderer @sketchi/diagram-renderer Deterministic scene generation remains independently testable.
packages/diagram/excalidraw @sketchi/diagram-excalidraw Sketchi scene to Excalidraw adapter.
packages/diagram/generation @sketchi/diagram-generation Provider request/response and candidate parsing.
packages/diagram/agent @sketchi/diagram-agent Canonical build runtime and artifact orchestration.
packages/diagram/scenarios @sketchi/diagram-scenarios Eval-only prompts, assertions, and scenarios.
packages/diagram/ui @sketchi/diagram-ui Rename from “studio UI”; it is shared by five surfaces.

Why not @sketchi/diagram/core?

npm package names allow @scope/package, not a second package namespace. That syntax would mean a subpath export from one monolithic @sketchi/diagram package, weakening Nx package boundaries and increasing the migration risk.

Recommended compromise

Group by filesystem path, retain explicit npm package names, and update pnpm-workspace.yaml to include packages/*/*. The tree becomes ergonomic without turning seven tested packages into one.

Combined boundary

Studio exists today, inside the Playground host

The current apps/studio is not merely misnamed. It owns public Playground, Code Mode, artifact routes, and a genuine persisted project/diagram foundation.

Do not

Blindly rename the directory

A direct apps/studio → apps/playground move would hide project records, diagram records, ownership, and /api/studio behind another incomplete name.

Extract first

Make the domain portable

Move Studio contracts and persistence into packages/studio/projects. The public Playground app may compose it temporarily; a future authenticated apps/studio can consume the same domain when it becomes a separate deployment.

API sanity check

src/routes/api is correct

These files are TanStack Start route adapters and deliberately map to HTTP paths. Hiding them elsewhere would make the framework boundary less obvious.

Keep

Thin route modules

apps/playground/src/routes/api/v1/..., api/studio/..., api/chat.ts, and routes/mcp.ts should continue to declare public transport contracts.

Move

Substantive server code

Move large *.server.ts implementations from src/lib to src/server/{chat,codemode,studio,bindings}. Route paths do not change.

Migration sequence

Small, reversible slices

Do not combine public HTTP changes with repository moves. Each phase should leave tests, builds, Storybook, previews, and the deployed route map green.

Review decisions

What approval means

The proposal intentionally separates decisions that are safe now from operational identities that need a later migration.

1

Approve the app identity map

eval-harness owns internal regression work; playground owns the public anonymous product and Code Mode host; packages/studio/projects owns the existing persistence domain; reserve apps/studio for a future separately deployed authenticated product.

2

Approve nested diagram folders

Adopt packages/diagram/* while retaining independent npm packages. This is the smallest change matching the requested ergonomics.

3

Preserve HTTP routes

Keep /api/v1, /api/studio, /api/chat, and /mcp stable during repository work. Revisit API product naming only with a versioned contract proposal.

4

Defer durable resource renames

Do not aesthetically rename R2 buckets, Pipeline streams, or externally configured Worker endpoints in the same changes. Migrate those only when there is operational value.

Secondary findings

Cleanup unlocked by the move

Dependency direction

Production diagram-generation currently depends on eval-focused diagram-scenarios. Move shared prompt contracts toward generation so scenarios depend on runtime code, not the reverse.

Workspace coverage

Add packages/*/* and tools/* deliberately to pnpm globs, or remove package semantics from tools. The current generator package is an Nx project but not a pnpm workspace package.

Enforced boundaries

Add Nx tags such as type:contract, type:runtime, type:eval, and type:app, then prevent runtime packages from importing eval or app code.
